# Setup walkthrough

Three machines, in this order: **Windows PC** (brain), **M7** (body + memory), **phone** (remote).
Budget an evening for PC + M7, and another for Google/ActivityWatch/phone extras.

```
 Phone ──Tailscale──▶ M7 :8000  (assistant API, scheduler, SQLite, Jarvis/Claude sandbox, 5TB vault)
                       │   ▲
          Ollama :11434│   │ /chat (voice client)
      host agent :8090 ▼   │
                     Windows PC (RTX 3070 Ti: Ollama · CPU: Whisper + Piper · ActivityWatch)
```

---

## Part 1: Windows PC

### PC-1. Install the basics
1. **Python 3.12** from python.org (tick *Add python.exe to PATH*).
2. **Ollama** from <https://ollama.com/download>.
3. **Git** for Windows.
4. **Tailscale** from <https://tailscale.com/download>; sign in.
5. **ActivityWatch** from <https://activitywatch.net> (set it to start with Windows). Add the browser
   extension if you want per-tab tracking.

### PC-2. Run the installer
In an **admin** PowerShell:
```powershell
git clone https://github.com/aidankeighron/personal-assistant.git C:\assistant
cd C:\assistant\pc
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -M7Ip <M7 tailscale IP>     # e.g. 100.101.102.103 (from `tailscale ip -4` on M7)
```
This creates a venv, installs the Python deps, configures and restarts Ollama (models unload
after 2 minutes idle, one model loaded at a time), adds firewall rules (M7 only), **downloads
every model automatically** (`pc\download_models.py`: the Piper voices in `config.yaml`, the
Whisper model, and the Ollama models), and registers three logon/weekly tasks: host agent,
voice client, and a weekly model re-check.

### Model downloads are automatic

| What | Where it runs | When |
|---|---|---|
| Ollama models the agents use (`models:` + agent YAMLs + `extra_models:` in M7's settings) | M7 pulls them onto the PC over Ollama's API | at M7 startup and every 6 h; skipped while a fullscreen game runs |
| Ollama models (first install, before M7 exists) | `download_models.py` on the PC (list from M7's `GET /models`, else `ollama_models:` in `pc\config.yaml`) | install + Sunday 4 AM |
| Piper voices listed in `pc\config.yaml` -> `tts.voices` | `download_models.py`, and `voice_client.py` at startup | install, startup, weekly |
| Whisper (`voice.whisper_model`) | `download_models.py` (faster-whisper cache) | install, weekly |

So to switch models you only edit config: change `models.fast` on M7 (or add a voice to
`pc\config.yaml`) and it's fetched automatically. Manual triggers if you're impatient:
`python -m assistant models --pull` on M7, or `.\.venv\Scripts\python.exe download_models.py` on the PC.

### PC-3. Measure your models (important)
```powershell
cd C:\assistant
python prototypes\rocky_harness.py
```
Try `/tier 1`, `/tier 2`, and compare first-response latency. Put the winners in M7's
`config/settings.yaml` under `models:`. With 8 GB VRAM, keep interactive models at 8B or below
(Q4). Also try newer families from the Ollama library (Qwen 3, Gemma, Llama) since Qwen2.5 is aging.

### PC-4. Edit `pc\config.yaml`
- `server.url`: `http://m7:8000` (M7's Tailscale name), `server.api_token`: from M7's `.env`.
- `host_agent.token`: generated by the installer; copy it into M7's `.env` as `PC_HOST_TOKEN`.
- `display_modes`: replace the `DisplaySwitch.exe` placeholders with your real display-switcher
  commands (NirSoft MultiMonitorTool `/LoadConfig` profiles work well; `nircmd setdefaultsounddevice`
  for audio).
- `apps`: your games/apps. Only what's listed here can be launched.
- `projector.browser_cmd`: set `--window-position` to where the projector sits in your display layout.

### PC-5. Wake-on-LAN (so Mother's 5 AM run can wake the PC)
1. BIOS: enable *Wake on LAN* / *Power On By PCI-E*.
2. Device Manager → network adapter → Power Management: *Allow this device to wake the computer*
   and *Only allow a magic packet*. Advanced tab: *Wake on Magic Packet* = Enabled.
3. Disable Fast Startup (Control Panel → Power Options → Choose what the power buttons do).
4. `getmac /v` → put the wired adapter's MAC in M7 `.env` as `PC_MAC`.
   WOL only works on the **LAN** (wired is most reliable), not over Tailscale.

### PC-6. Test
```powershell
cd C:\assistant\pc
.\.venv\Scripts\python.exe host_agent.py        # leave running (it autostarts at next logon)
.\.venv\Scripts\python.exe voice_client.py --text   # type "hey rocky what's the weather"
.\.venv\Scripts\python.exe voice_client.py          # say "Hey Rocky, what time is it?"
```
If wake-word mode triggers on noise, raise `voice.energy_threshold`, or use `--ptt`.

## Part 2: M7 server

### M7-1. OS
Install **Ubuntu Server 24.04 LTS** on M7's internal drive. During install: enable OpenSSH,
create your user. Everything else is scripted. (HDD boot drive is fine: the assistant uses
SQLite in WAL mode and very little I/O.)

### M7-2. Tailscale + clone
```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
git clone https://github.com/aidankeighron/personal-assistant.git ~/personal-assistant
```
In the Tailscale admin console, rename the machine to `m7` and the PC to `desktop`
(or change the hostnames in `.env`).

### M7-3. Mount the 5TB drive
```bash
lsblk -f                                  # find it, e.g. sdb1, and its UUID
# Only if it's empty / you're OK wiping it:  sudo mkfs.ext4 -L vault /dev/sdb1
sudo mkdir -p /mnt/vault
echo 'UUID=<uuid> /mnt/vault ext4 defaults,nofail,noatime,x-systemd.device-timeout=30 0 2' | sudo tee -a /etc/fstab
sudo mount -a && df -h /mnt/vault
```
If it's NTFS (Dad's drive with data on it), it works with `ntfs3` instead of `ext4` in fstab,
but ext4 is much more reliable for a database. Copy data off and reformat if you can.

Stop USB power-saving from dropping the drive: add `usbcore.autosuspend=-1` to
`GRUB_CMDLINE_LINUX_DEFAULT` in `/etc/default/grub`, then `sudo update-grub`.

### M7-4. Install
```bash
sudo bash ~/personal-assistant/deploy/m7/install.sh
```
This installs Docker, creates the `assistant` service user, copies the code to `/opt/assistant`,
builds the sandbox image, starts the `pa-sandbox` container, registers the assistant's own repo as a
Jarvis project, opens port 8000 on Tailscale only, and starts the `assistant` systemd service.

### M7-5. Configure
```bash
sudo -u assistant nano /opt/assistant/.env                    # PC_HOST, PC_HOST_TOKEN, PC_MAC, NTFY_TOPIC
sudo -u assistant nano /opt/assistant/config/settings.yaml    # models, timezone, collectors
```
`init` already generated `ASSISTANT_API_TOKEN`, `PC_HOST_TOKEN` (replace with the PC's) and a random
`NTFY_TOPIC`.

### M7-6. Log Claude Code in (for Jarvis)
```bash
sudo docker exec -it pa-sandbox claude        # complete the login, then /exit
```
The login is saved to `/mnt/vault/assistant/claude-home` and reused by every Jarvis run.
(Alternatively set `ANTHROPIC_API_KEY` in `.env` to bill an API key.)

### M7-7. Check everything
```bash
sudo systemctl restart assistant
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant doctor
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant models     # which models, which are missing
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant chat
journalctl -u assistant -f            # logs
```

## Part 3: Phone

1. Install **Tailscale** (same account) and the **ntfy** app. In ntfy, subscribe to your
   `NTFY_TOPIC` (server `https://ntfy.sh` unless you self-host).
2. Open `http://m7:8000/app`, enter the API token, and *Add to Home Screen*. That's your phone client.
3. **Voice on the phone** needs HTTPS. On M7: `sudo tailscale serve --bg 8000`, then use the
   `https://m7.<tailnet>.ts.net/app` URL and set `ASSISTANT_PUBLIC_URL` to it (also makes the
   ntfy Approve buttons and HUD links work from anywhere on your tailnet).
4. **Location / grocery tracking**: install **OwnTracks** → Mode *HTTP* → URL
   `https://m7.<tailnet>.ts.net/location?token=<API token>`. Create regions (*Regions* tab) for your
   stores (named e.g. "Kroger") plus Home, Gym. Leaving a store triggers *"What did you buy?"*
   and your answer to Rocky goes into the fridge tracker.
   (Tasker / iOS Shortcuts work too: POST `{"event":"leave","place":"Kroger"}` to the same URL.)

## Part 4: Data sources

| Source | How |
|---|---|
| PC usage | ActivityWatch on the PC (enabled by default, relayed by the host agent) |
| Gmail / Calendar / Drive | See below, then add `gmail, gcal, drive` to `collectors.enabled` |
| GitHub | Set `collectors.github.username` (+ `GITHUB_TOKEN` for private activity), enable `github` |
| Daily notes | Rocky's `take_note`, or put `.md` files in `/mnt/vault/assistant/notes/` (or list a synced folder in `collectors.notes.dirs`) |
| Finances, LinkedIn, Half Full, Wispr Flow, phone usage, browser history exports | Drop CSV/JSON/JSONL/MD into `/mnt/vault/assistant/inbox/<source>/`. Each file becomes events tagged `<source>` |
| Anything that can make an HTTP call (Tasker, Shortcuts, scripts) | `POST /ingest/<source>?token=...` with a JSON object or list |
| Location | OwnTracks (above) |

**Google setup (once):**
1. <https://console.cloud.google.com> → new project → enable Gmail API, Calendar API, Drive API.
2. OAuth consent screen: External, add yourself as a test user.
3. Credentials → Create OAuth client ID → *Desktop app* → download JSON.
4. On the **PC** (has a browser), from `C:\assistant`:
   `pc\.venv\Scripts\pip install google-auth-oauthlib` then
   `pc\.venv\Scripts\python -m assistant auth-google --client-secret client_secret.json --out token.json`
5. Copy `token.json` to M7: `/mnt/vault/assistant/google/token.json` (owned by `assistant`).

Test a collector any time: `python -m assistant collect gmail`.

`/mnt/vault/projects/personal-assistant`, merge it on GitHub, then `sudo bash /opt/assistant/deploy/m7/update.sh`.

## Hardening (do these once it works)

- **Rootless Docker.** The `assistant` user is in the `docker` group (root-equivalent on M7).
  M7 holds nothing from the PC, so this is acceptable to start. To tighten, switch to rootless
  Docker (`dockerd-rootless-setuptool.sh install` as `assistant`) and set `DOCKER_HOST`.
- **Off-box backups.** Set `backup.target` to an rsync destination that isn't the vault drive
  (e.g. a share on the PC). Skynet warns if backups go stale.
- **Self-host ntfy** (`docker compose --profile ntfy up -d`) so notifications don't touch ntfy.sh.
- **Keep the host agent narrow.** Add apps/profiles in `pc/config.yaml`; never add a shell endpoint.
