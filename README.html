Local multi-agent personal assistant

Rocky · Jarvis · Mother · Skynet

Four agents with their own jobs and voices. Your Windows PC is the brain: it runs the models on the RTX 3070 Ti. A cheap M7 server is the body and the memory: it runs the agents, stores everything on a 5TB drive, and is the agents' sandbox.

RockyEveryday real-time voice. Weather, timers, PC control, fridge.
JarvisCoding. Runs Claude Code after you approve, reads you status updates.
MotherYour data. Nightly morning brief, analysis, reports you can reshape.
SkynetBackground audits: security, backups, memory sanity.

Set up the M7 server

Do the server first: the PC installer needs the server's Tailscale IP. Plan on an evening. The server runs Ubuntu Server, keeps everything on the 5TB drive, and runs one light Python service plus Docker for the sandbox.

Haven't set up M7 yet? Run the server on your Windows PC first

The server code runs on Windows too, for testing. Everything goes in .\data inside the repo. You need Python, Git for Windows (its bash is the agents' shell in this mode), Ollama, and optionally Claude Code for Jarvis.

powershell
cd C:\assistant
Set-ExecutionPolicy -Scope Process Bypass
.\deploy\windows\start-server.ps1        # add -WithDocker to use Docker Desktop containers

It sets up a Python environment, writes single-machine settings (init --local), checks everything, prints the web app link and starts the server. For voice and PC control, also run pc\install.ps1 -M7Ip 127.0.0.1 as admin, then start-server.ps1 again so it pairs the tokens.

Not sandboxed: in this mode the agents' shell is Git Bash on your PC and Jarvis uses your own claude. Use -WithDocker for container isolation, and move to M7 for the real setup.

  1. Install the OS

    Install Ubuntu Server 24.04 LTS on M7's internal drive. Enable OpenSSH and create your user during install. A hard-drive boot disk is fine: the assistant uses SQLite and very little I/O.

  2. Tailscale and the code

    bash
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
git clone https://github.com/aidankeighron/personal-assistant.git ~/personal-assistant

    In the Tailscale admin console, rename this machine to m7 and your PC to desktop (or use other names and put them in .env). Note the IP from tailscale ip -4; the PC installer needs it.

  3. Mount the 5TB drive at /mnt/vault

    bash
    lsblk -f                      # find the drive and its UUID
sudo mkdir -p /mnt/vault
echo 'UUID=<uuid> /mnt/vault ext4 defaults,nofail,noatime,x-systemd.device-timeout=30 0 2' | sudo tee -a /etc/fstab
sudo mount -a && df -h /mnt/vault
    Tip: ext4 is far more reliable for a database than NTFS. If the drive already holds data, copy it off and reformat if you can. To stop USB power-saving from dropping the drive, add usbcore.autosuspend=-1 to GRUB_CMDLINE_LINUX_DEFAULT in /etc/default/grub, then run sudo update-grub.

  4. Run the installer

    bash
    sudo bash ~/personal-assistant/deploy/m7/install.sh

    Safe to re-run. It:

    • installs Docker and creates an assistant service user
    • copies the code to /opt/assistant and generates .env with random tokens
    • builds the sandbox image and starts the pa-sandbox container
    • registers the assistant's own repo as a Jarvis project, so Jarvis can improve itself
    • opens port 8000 on Tailscale only and starts the assistant systemd service

  5. Configure

    bash
    sudo -u assistant nano /opt/assistant/.env
sudo -u assistant nano /opt/assistant/config/settings.yaml   # models, timezone, data sources
    .env keyWhat to put there
    ASSISTANT_API_TOKENGenerated for you. Every client (PC, phone) uses it.
    PC_HOSTThe PC's Tailscale name, e.g. desktop.
    PC_HOST_TOKENReplace with the token the PC installer prints (step 2 of PC setup).
    PC_MACThe PC's wired MAC address, for Wake-on-LAN before the 5 AM run.
    NTFY_TOPICGenerated. Subscribe to it in the ntfy phone app.
    GITHUB_TOKENOptional: lets Mother see private GitHub activity.

  6. Log Claude Code in for Jarvis

    bash
    sudo docker exec -it pa-sandbox claude    # complete the login, then /exit

    The login is saved on the vault and reused by every Jarvis run. Or set ANTHROPIC_API_KEY in .env to use an API key instead of your subscription.

  7. Check everything

    bash
    sudo systemctl restart assistant
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant doctor   # can M7 reach the PC?
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant models   # required vs installed models
sudo -u assistant /opt/assistant/.venv/bin/python -m assistant chat     # talk to the agents in the terminal
journalctl -u assistant -f                                               # live logs

Hardening, once it works

Off-box backups

Set backup.target to an rsync destination that isn't the vault drive, such as a share on the PC. Skynet warns when backups go stale.

Rootless Docker

The assistant user is in the docker group, which is root-equivalent on M7. That's acceptable to start because M7 holds nothing from the PC; switch to rootless Docker to tighten.

Self-host notifications

docker compose --profile ntfy up -d runs ntfy on M7 so pushes never touch ntfy.sh.

Keep the PC whitelist narrow

Add apps and display profiles in pc/config.yaml. Never add a shell endpoint to the host agent.

Set up the Windows PC

The PC runs the models and the voice. It never runs agent code: M7 can only use a short whitelist of actions you define. One PowerShell script does almost everything, including downloading every model.

  1. Install the basics

    • Python 3.12 from python.org (tick Add python.exe to PATH)
    • Ollama from ollama.com/download
    • Git for Windows
    • Tailscale, signed in to the same account as M7
    • ActivityWatch, set to start with Windows (plus the browser extension for per-tab tracking)

  2. Run the installer

    In an administrator PowerShell:

    powershell
    git clone https://github.com/aidankeighron/personal-assistant.git C:\assistant
cd C:\assistant\pc
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1 -M7Ip <M7 tailscale IP>

    It creates a Python environment, configures and restarts Ollama (models unload after 2 minutes idle, one model at a time), allows only M7 through the firewall, downloads every model, and registers three Task Scheduler jobs: the host agent, the voice client, and a weekly model re-check. It prints a host_agent.token; put that in M7's .env as PC_HOST_TOKEN.

  3. Models download themselves

    WhatFetched byWhen
    Ollama models the agents useM7 pulls them onto the PC over Ollama's APIM7 startup, then every 6 h. Waits while a game is fullscreen.
    Ollama models on first installPC download_models.py, list taken from M7Install, Sundays 4 AM
    Piper voices in pc\config.yamlPC download_models.py, voice clientInstall, voice client start, weekly
    Whisper speech modelPC download_models.pyInstall, weekly

    To switch models you only edit config: change models.fast on M7, or add a voice to pc\config.yaml, and it's fetched automatically.

  4. Measure your models

    powershell
    cd C:\assistant
python prototypes\rocky_harness.py

    Compare first-response speed between tiers and put the winners under models: in M7's settings.yaml.

    8 GB of VRAM: keep interactive models at 8B parameters or less (Q4). A 14B model won't fit and spills into system RAM. Also try newer families in the Ollama library; Qwen2.5 is the default, not the best.

  5. Edit pc\config.yaml

    • server.url = http://m7:8000, server.api_token = M7's ASSISTANT_API_TOKEN
    • display_modes: replace the placeholders with your real display switcher commands (movie, racing, desk, projector)
    • apps: the games and apps Rocky may open. Nothing else can be launched.
    • projector.browser_cmd: set --window-position to where the projector sits in your layout
    Two tokens, swapped once: M7's ASSISTANT_API_TOKEN goes into the PC's server.api_token, and the PC's host_agent.token goes into M7's PC_HOST_TOKEN.

  6. Wake-on-LAN, for Mother's 5 AM run

    • BIOS: enable Wake on LAN / Power On By PCI-E
    • Device Manager → network adapter → Power Management: allow it to wake the PC, magic packet only
    • Turn off Fast Startup in Power Options
    • getmac /v → wired adapter's MAC into M7's PC_MAC. Works on the home network, not over Tailscale.
    Sleep, don't shut down. Ollama and the host agent run in your logged-in session. A shut-down PC woken at 5 AM stops at the login screen with neither running, so there'd be no model for the morning brief.

  7. Test

    powershell
    cd C:\assistant\pc
.\.venv\Scripts\python.exe host_agent.py              # autostarts at next logon
.\.venv\Scripts\python.exe voice_client.py --text     # type "hey rocky what's the weather"
.\.venv\Scripts\python.exe voice_client.py            # say "Hey Rocky, what time is it?"

    If the wake word triggers on background noise, raise voice.energy_threshold or use push-to-talk with --ptt.

Set up data collection

Mother can only answer questions about data she has. Each source below takes 5–15 minutes, once. Start with the automatic ones; add the rest whenever you like. Everything lands in one database on M7, tagged by source.

Automatic

Collectors on M7 pull these every 30 minutes once they're set up: ActivityWatch, Google, GitHub, notes folders.

Upload

For apps with no API (bank, LinkedIn, Half Full): export a file and tap ⬆ Upload in the web app on your PC or phone. CSV, JSON, Markdown, text, or a whole .zip. Ingested immediately.

Phone automation

Your phone sends events as they happen: OwnTracks for places, and iOS Shortcuts or Android Tasker for app use. All go to /ingest/<source> over Tailscale.

Before you start

  • Phone on Tailscale (same account as M7) and, for HTTPS, sudo tailscale serve --bg 8000 on M7. Your base URL is then https://m7.<tailnet>.ts.net; the examples call it $M7.
  • Your API token (ASSISTANT_API_TOKEN) is shown below as $TOKEN. Phone automations pass it as ?token=….
  • Collectors are switched on in M7's config/settings.yaml under collectors.enabled, then sudo systemctl restart assistant.

Gmail, Calendar, Drive

Automatic

Location

Phone automation

Places you arrive at and leave. Leaving a grocery store makes Rocky ask what you bought, which feeds the fridge tracker.

iPhone or Android
  1. Install OwnTracks.
  2. Settings → Connection → Mode HTTP. URL:
    url
    $M7/location?token=$TOKEN
  3. Regions → add places by name: Home, Gym, and each store (Kroger, Meijer…).
  4. Allow location Always so region exits fire in the background.
Good to know
  • Store names come from groceries.store_keywords in settings.yaml; add your own.
  • Rather not run OwnTracks? A Shortcuts/Tasker automation can POST {"event":"leave","place":"Kroger"} to the same URL.

Phone usage

Phone automation

Screen Time (iOS) and Digital Wellbeing (Android) have no export or API, so the phone reports app opens itself. Pick the apps you care about; you don't need all of them.

iPhone: Shortcuts
  1. Shortcuts → Automation → + → App → choose apps → Is Opened → Run Immediately.
  2. Action: Get Contents of URL, method POST, URL $M7/ingest/phone_usage?token=$TOKEN.
  3. Request body JSON: app = the app's name, event = open.
  4. Optional: a second automation on Is Closed with event = close, for durations.
Android: Tasker or Automate
  1. Tasker (paid) or Automate (free): new profile → Application → pick apps.
  2. Task: HTTP Request, POST to $M7/ingest/phone_usage?token=$TOKEN.
  3. Body: {"app":"%app","event":"open"} with header Content-Type: application/json.
  4. Add an exit task with "event":"close" for durations.

How it works

Every message, from any surface, goes to one service on M7. A router picks the agent, the agent uses the PC's model and its tools, and the reply streams back.

The agents

Rocky

A local model in a tool-calling loop with 22 tools: weather, timers, notes, memory, PC display modes and apps, the projector, the fridge, a sandboxed shell. A rule-based filter keeps the Project Hail Mary voice even on a small model.

Jarvis

Not a chatbot. A small model sorts your request into list / status / build / new / cancel, and Jarvis answers from templates filled with project state. The real work is Claude Code, running in a container.

Mother

A bigger model with data tools: describe the data, run read-only SQL, run and edit reports. Builds the morning brief every night while you sleep.

Skynet

Rules, not guesses: expired approvals, disk space, backups, broken data sources, failed runs, leaked keys in Jarvis's projects, missing models, and memory facts that contradict the hardware.

Want a fifth agent? Add a YAML file in config/agents/ with a persona and a tool list. No code needed.

The nightly run

05:00 Collect from every data source (CPU only, on M7)
05:01 Wake the PC with Wake-on-LAN if it's asleep
05:02 Wait until the GPU is free: night window, or you've been away 10 minutes and nothing is fullscreen
05:05 Build the morning brief: schedule, email digest, weather, food expiring, project status
05:10 Pull lasting facts from yesterday's conversations, then generate the daily report
05:15 Skynet audit, database backup, push "brief ready"

Reports you can reshape

A report is a YAML file: sections (which data, what to say) plus standing instructions. Say "for future reports, add X" and Mother edits it; old versions are kept. The defaults are a daily report and a weekly review.

Memory without the creepiness

VerifiedChecked against telemetry, like the GPU from nvidia-smi.
ExplicitYou said it: "remember…", "from now on…". Trusted immediately.
CandidateExtracted overnight. Needs to come up 3 times before it counts.
QuarantinedContradicted or stale, like "you have a 3080". Never used.

Facts are only given to an agent when their topic matches your request, with a rule never to mention a fact just to show it knows it. Ask for Python help and your car won't come up.

The split between the PC and the server

The PC has the GPU, so it does inference and nothing else heavy for the assistant. The server is cheap and always on, so it does orchestration, storage, schedules and anything risky. Neither can do the other's job well.

Windows PC

Runs only what needs the GPU, or has to be physically on the PC.

GPU
Ollama models. Unload after 2 minutes, one at a time.
CPU
Whisper (speech to text), Piper (agent voices).
Exposes
Ollama :11434 and the host agent :8090, to M7 only.
Never
Runs agent code, or gives M7 a shell.
Off?
Rocky and Mother say the brain is offline. The 5 AM run wakes it.

M7 server

Everything that's cheap, always-on, or risky.

Runs
The agents, tools, scheduler, collectors, web app, API.
Stores
All memory and data on the 5TB vault (SQLite).
Sandbox
Docker containers for the agents' shell and Jarvis's Claude Code.
Exposes
:8000, on Tailscale only.
Works without the PC
Reminders, push alerts, Jarvis status, Skynet, data collection.
